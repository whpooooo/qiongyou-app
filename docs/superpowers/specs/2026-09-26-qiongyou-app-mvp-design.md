# 学生与年轻背包客路线规划 Web 原型设计稿

日期：2026-09-26

## 1. 产品定义

### 1.1 产品定位

本产品面向国内学生和年轻背包客，帮助他们在有限预算内完成三件事：

1. 比较穷游路线和交通方案。
2. 通过“下一站，未知”发现适合当前假期的目的地。
3. 在“旅人现场”查看和讨论走过相同路线的人提供的真实经验。

第一版是手机优先的 Web 原型，不替代票务平台，不在产品内处理订单、支付、退改签或售后。

### 1.2 核心价值

- 用户知道目的地时，快速得到三套差异明显的路线方案。
- 用户不知道目的地时，得到有理由、有期待感的惊喜推荐。
- 用户挑选方案时，能直接比较总费用、总耗时、换乘次数、到达时间和预算结余。
- 用户做决定前，能看到走过相似路线的人提供的真实花费、经验与避坑提醒。

### 1.3 第一版目标

- 用户进入首页即可看到路线规划输入区。
- 用户在一分钟内完成条件填写并获得三套可比较方案。
- 首页提供足够有吸引力的“下一站，未知”和“旅人现场”内容，形成继续使用和互动动机。
- 用模拟数据完成完整流程，同时保留可替换的实时数据和购票跳转接口。
- 记录关键行为，以便后续判断哪些模块真正留住用户。

### 1.4 第一版不包含

- 站内支付、下单、退改签和票务售后。
- 普通用户注册、登录和跨设备同步。
- 真实社交媒体关系、私信和实时聊天。
- 全国任意城市覆盖。
- 自建实时地图导航。

## 2. 用户与范围

### 2.1 目标用户

- 国内大学生。
- 刚工作、预算有限的年轻旅行者。
- 能接受较长时间交通和中转换乘的背包客。
- 希望低成本结伴出行，但不愿意自己从零查路线的人。

### 2.2 覆盖范围

- 覆盖所有省级行政中心的省会、首府和直辖市。
- 覆盖学生与年轻用户常去的热门旅游城市。
- 城市选择覆盖上述范围；热门线路使用精编模拟数据，非热门城市对使用基于距离和交通方式的通用估算。
- 数据必须明确标注“模拟预估”或“实时查询”，不得把模拟结果伪装成实时结果。

### 2.3 核心使用场景

1. 用户假期确定，但不知道去哪，希望快速得到有理由的目的地推荐。
2. 用户已经确定出发地、目的地、预算和天数，希望比较不同交通组合。
3. 用户已看到一条攻略，希望基于攻略中的路线生成自己的方案。
4. 用户完成或准备一趟旅行，希望在对应路线主题下查看和发布经验。
5. 用户保存若干方案，在后续比较、调整或出行时再次使用。

## 3. 信息架构与页面

### 3.1 首页

首页是本产品的主入口，不做传统门户式铺陈，首屏直接展示规划工具。

首屏包含：

- 清晰的价值主张，例如“预算有限，也能去很远”。
- 预算输入。
- 人数与同行类型输入。
- 出发地和目的地输入。
- 出发日期、返程日期或旅行天数输入。
- 城际交通方式选择。
- 出行优先级选择。
- 主按钮“生成 3 套穷游方案”。

交互要求：

- 使用大字号、大按钮、强对比和少层级。
- 核心输入可以在首屏看到，不要求用户先进入其他页面。
- 目的地允许使用“不知道去哪”状态，并引导进入“下一站，未知”。

首页后续内容顺序：

1. “下一站，未知”推荐模块。
2. 热门路线模块。
3. “旅人现场”精选内容模块。

### 3.2 “下一站，未知”推荐模块

模块定位：

- 是产品最具特色的功能，不是普通目的地列表。
- 让用户把期待变成惊喜，同时确保推荐可解释、可执行。
- 推荐结果不是纯随机，而是基于用户条件计算后的结果。

模块标题：

- 主标题：“下一站，未知”
- 副标题：“给我一个假期，还你一个没想到的目的地”
- 主按钮：“给我一个惊喜”
- 次按钮：“先看看能去哪”

输入条件：

- 当前所在位置。
- 可出行天数。
- 预算。
- 出行月份或日期。
- 同行类型。
- 兴趣偏好。

排序方式：

- 综合推荐。
- 花费最低。
- 交通最省心。
- 季节最合适。

同行类型作为筛选条件，不参与排序按钮。同行类型包括独自、两人、朋友结伴和家庭。

揭晓流程：

1. 用户提交条件。
2. 页面通过地图点亮或卡片翻转制造揭晓感。
3. 先展示一个“最惊喜目的地”。
4. 同时展示两个备选目的地。
5. 每个目的地显示推荐理由、预计总花费、建议天数、交通方式和当季亮点。
6. 用户选择“就它了”后，带入规划表单并生成三套路线方案。
7. 用户可以“换一个”或收藏推荐结果。

### 3.3 路线规划

用户输入：

- 总预算。
- 人数与同行类型。
- 出发地。
- 目的地。
- 途径点（可选，最多 3 个）。
- 出发日期。
- 旅行天数或返程日期。
- 可接受交通方式。
- 省钱、平衡、省时等优先级。
- 可选条件：日期弹性、夜车、红眼航班、凌晨到达、换乘上限、行李、学生优惠、住宿类型和饮食标准。

城际交通方式：

- 飞机。
- 火车和高铁。
- 长途客车。
- 租车或自驾。

市内交通默认允许公交、地铁、步行和共享单车，并计入市内交通预算。

途径点按顺序进入路线，每个途径点可设置停留天数。系统按“出发地 → 途径点 → 目的地”逐段估算交通、时间、住宿和费用，并在方案中显示绕行增加的成本。

输出：

- 极限省钱。
- 均衡推荐。
- 省时优先。

每套方案展示：

- 总费用与费用区间。
- 总耗时。
- 换乘次数。
- 最晚到达时间。
- 城际交通组合。
- 住宿与餐饮标准。
- 每日行程摘要。
- 预算结余或超支。
- 数据来源标识。

### 3.4 方案比较

三套方案必须同时保留，不替用户做最终决定。

比较表固定显示：

- 总费用。
- 总耗时。
- 换乘次数。
- 最晚到达时间。
- 住宿标准。
- 餐饮预算。
- 市内交通预算。
- 门票和其他费用。
- 最终结余。

点击任意方案后，展示按天展开的交通、住宿、活动和费用明细。每个价格项区分模拟预估、用户历史贡献和实时查询。

### 3.5 热门路线

热门路线卡片展示：

- 完整路线链，包括出发城市、途径点与目的地城市。
- 适合天数。
- 最低预计预算。
- 典型耗时。
- 推荐交通方式。
- 已聚合的经验数量。
- 每个途径点的建议停留天数。

进入路线详情后，用户可以查看按“出发地、途径点、目的地”分段的行程时间线，了解每段交通、停留天数、住宿和费用。用户可以一键带入规划器，也可以收藏路线、查看经验或参与讨论。

### 3.6 “旅人现场”社区

社区名称不使用“穷游社区”“省钱攻略墙”。

模块名称：

- 主标题：“旅人现场”
- 副标题：“只看真去过的人怎么说”

内容重点：

- 真人。
- 真路线。
- 真花费。
- 真避坑。

聚合规则：

- 主主题由出发城市、目的地城市和天数区间组成。
- 子主题表示同一路线下的不同玩法，例如省钱夜车版、舒适高铁版、学生党三日版。
- 相同或相近路线的心得放在同一主题下，避免内容散落。

第一版社区操作：

- 浏览路线主题。
- 查看攻略和真实花费。
- 查看讨论与问答。
- 收藏主题。
- 模拟发布攻略和经验。
- 模拟评论和点赞。

### 3.7 我的

“我的”展示：

- 已保存方案。
- 已收藏路线。
- 用户发布的经验和讨论。
- 用户参与过讨论的路线。

第一版使用浏览器本地数据模拟个人状态，不要求注册登录。

### 3.8 底部导航

底部导航只保留少量入口：

- 首页。
- 下一站。
- 旅人现场。
- 我的。

首页展示目的地推荐摘要，“下一站”进入完整的“下一站，未知”推荐页。已保存方案和收藏统一放入“我的”。

### 3.9 图片与视觉吸引力

- 首页主视觉必须有图片，不只使用纯色背景和文字。
- 热门路线卡必须显示本地风景图，不使用远程图片或未授权素材。
- “下一站，未知”的主推荐和备选卡必须显示目的地图片。
- 热门路线详情头图必须显示对应路线图片。
- 旅人现场精选内容显示所在路线缩略图。
- 第一版使用统一风格的原创 SVG 风景插画，后续可以替换为正式摄影素材。
- 图片必须有可读的替代文字，加载失败时仍保留清晰背景和文字内容。
### 3.10 PWA 安卓与 iOS 交付

- 第一版安卓交付采用 PWA，不要求用户下载 APK。
- Android Chrome 支持直接打开 HTTPS 地址并添加到主屏幕。
- iPhone 使用 Safari 的“分享 → 添加到主屏幕”。
- PWA 必须提供本地图标、应用名称、主题色、全屏独立运行和启动背景。
- Service Worker 必须缓存首页、样式、脚本、数据、图片和图标，支持离线打开。
- 浏览器不支持 Service Worker 或通过本地 `file://` 打开时，应用仍能正常作为普通网页运行。
- 第一版不启用推送通知、后台同步、蓝牙或原生文件系统权限。
- 浏览器本地数据可能被系统清理，重要方案后续仍需云端账号同步。
- PWA 必须通过 HTTPS 或 localhost 访问才能安装和启用离线缓存。
## 4. 数据与推荐逻辑

### 4.1 数据组成

路线数据包含：

- 城市资料。
- 途径点与停留天数。
- 城际交通段。
- 预计票价区间。
- 预计耗时。
- 换乘点与换乘等待。
- 市内交通。
- 住宿。
- 餐饮。
- 门票与其他费用。
- 路线模板。
- 用户经验与讨论。

### 4.2 费用估算

总费用由以下部分组成：

`城际交通 + 市内交通 + 住宿餐饮 + 景点及其他`

方案必须显示费用区间，而不是制造虚假的精确价格。显示内容包括：

- 最低可能费用。
- 正常预估费用。
- 预算缓冲。
- 用户总预算结余或超支。

### 4.3 三套路线策略

极限省钱：

- 以总费用最低为首要目标。
- 允许夜车、长途客车、多次换乘和较长等待。
- 在预算内优先选择低价交通和低成本住宿。

均衡推荐：

- 以不超预算为前提。
- 综合控制换乘次数、晚到时间、单段交通时长和等待时间。
- 是首页默认展开的方案。

省时优先：

- 以总耗时最短为首要目标。
- 总费用不得明显超过用户预算。
- 允许费用高于另外两套方案，但必须清楚展示超支风险。

### 4.4 目的地推荐评分

综合评分包含：

- 预算匹配度。
- 交通便利度。
- 当季适宜度。
- 同行类型适配度。
- 兴趣匹配度。
- 路线热度。

每个推荐目的地必须展示可读的推荐理由，不能只给排序结果。

### 4.5 推荐过程的可信度

- 推荐结果来自规则和评分，不使用欺骗性的随机动画。
- 如果数据不足，明确说明推荐置信度较低。
- 用户可以查看为什么推荐、预计花费如何计算。
- “换一个”请求应排除刚刚展示过的主推荐，同时保持条件一致。

## 5. 技术方案

### 5.1 第一版形态

- 手机优先的静态 Web 原型。
- 使用 HTML、CSS 和原生 JavaScript。
- 不依赖安装 Node、Python 或第三方前端框架。
- 页面可以通过静态文件直接打开，也可以用任意静态文件服务器托管。
- 数据与状态使用随应用加载的 JavaScript 数据和浏览器本地存储。

### 5.2 模块边界

- 路线规划器：收集条件并生成方案。
- 目的地推荐器：筛选、评分、排序并揭晓目的地。
- 方案比较器：计算展示差异并支持方案切换。
- 班次数据接口层：定义统一的查询接口，第一版返回模拟数据。
- 热门路线与方案保存：展示推荐线路，并支持保存到“我的”。
- 旅人现场：按路线主题聚合内容并模拟互动。
- 行为记录器：记录关键操作，第一版保存在本地，供后续分析。

### 5.3 实时数据接口边界

第一版定义统一接口：

- 查询两点之间的交通方案。
- 查询指定日期的预计或实时班次。
- 返回价格、时间、换乘、数据时间和数据来源。
- 返回可跳转的官方购票链接。

第一版只实现模拟数据提供器。后续接入有授权的服务时，通过新增数据提供器替换模拟数据，不修改页面流程和比较逻辑。

实时数据不可用时：

- 保留已经生成的模拟方案。
- 明确显示失效的数据项。
- 购票按钮显示接入说明，不伪造真实班次或购票链接。

### 5.4 安全与合规

- 真实数据服务的密钥不得放入浏览器代码。
- 接入真实服务时增加轻量后端，页面只访问后端接口。
- 只跳转官方或经过授权的票务渠道。
- 不保存支付信息，不代替用户完成订单。
- 第三方数据必须遵守其授权、展示、缓存和跳转要求。

## 6. 错误处理与边界状态

- 缺少必填条件时，指出具体字段，不生成不完整方案。
- 预算过低时，展示最低可行费用和需要放宽的条件。
- 没有可用路线时，推荐最接近的出发地或目的地。
- 日期不可用时，提示调整日期或改选其他目的地。
- 某一种交通方式不可用时，保留其他交通组合并解释原因。
- 实时数据接口失败时，继续使用明确标识的模拟方案。
- 社区主题没有内容时，展示相关路线和发布入口，不显示空白页。
- 所有模拟数据、估算数据和实时数据必须使用不同标识。

## 7. 行为记录

第一版记录以下关键行为：

- 首页规划表单开始填写。
- 三套方案生成成功。
- 三套方案对比打开。
- 单个方案详情打开。
- “下一站，未知”打开。
- 惊喜推荐揭晓。
- “换一个”点击。
- 推荐目的地带入规划器。
- 热门路线打开。
- 旅人现场打开。
- 路线经验打开。
- 模拟发布、评论、点赞和收藏。
- 购票跳转点击。
- 方案保存和再次打开。

记录保存在浏览器本地，后续接入正式分析服务时替换存储实现。

## 8. 验收标准

### 8.1 首页

- 用户首次进入就能看到规划表单的主要字段。
- 首屏有清晰的主按钮“生成 3 套穷游方案”。
- 首页下方依次出现“下一站，未知”、热门路线和“旅人现场”。
- 移动端宽度下无横向溢出，关键按钮易于点击。

### 8.2 路线规划

- 必填字段校验准确。
- 同一组合法条件下稳定生成三套方案。
- 三套方案在费用、耗时或换乘上存在可解释差异。
- 用户可以切换到对比表。
- 用户可以查看每日明细和费用组成。
- 用户可以添加最多 3 个途径点，并看到每段行程与费用变化。
- 数据来源标识正确。

### 8.3 下一站，未知

- 四个排序按钮均能改变结果顺序。
- 同行类型、预算、月份和兴趣筛选能改变结果集合。
- 揭晓页包含一个主推荐和两个备选。
- 每个结果包含推荐理由、预计费用、建议天数和交通方式。
- “就它了”可以把目的地带入规划表单。
- “换一个”不会重复当前主推荐。

### 8.4 旅人现场

- 相同出发城市、目的地城市和天数区间的经验归入同一主主题。
- 不同玩法可以成为独立子主题。
- 用户可以打开经验、讨论、收藏并模拟互动。
- 没有内容的路线主题有合理空状态。

### 8.5 实时接口与购票

- 模拟数据始终标明为模拟。
- 数据接口层不依赖具体供应商。
- 接口不可用时页面不崩溃。
- 购票按钮只在有真实授权链接时跳转；没有时明确说明尚未接入。

### 8.6 保存与个人状态

- 用户可以保存方案和收藏路线。
- 页面刷新后本地保存内容仍然存在。
- 用户可以再次打开已保存方案。

## 9. 测试策略

### 9.1 功能测试

- 预算边界、人数边界和日期边界。
- 单独选择飞机、火车、长途客车和租车。
- 飞机 + 火车、飞机 + 客车、火车 + 客车和包含租车的组合。
- 三套方案生成、对比、详情和保存。
- 途径点添加、删除、排序、停留天数和分段估算。
- 目的地推荐的四种排序和全部筛选条件。
- 惊喜推荐带入规划器的完整链路。
- 路线主题聚合、经验浏览和模拟社区互动。
- 实时接口不可用与购票链接缺失。

### 9.2 交互与显示测试

- 常见手机宽度下的首屏展示。
- 大按钮点击区域和表单可用性。
- 长城市名、长路线名和金额溢出。
- 空状态、加载状态、错误状态和模拟数据提示。

### 9.3 数据一致性测试

- 方案费用相加与总额一致。
- 途径点顺序与各分段路线一致。
- 方案比较表中的数值与详情一致。
- 推荐排序与显示的评分理由一致。
- 路线聚合键一致。
- 数据来源标识与实际提供器一致。

## 10. 后续版本边界

在第一版验证后，再评估以下能力：

- 接入有授权的实时交通数据。
- 增加后端服务并安全保存接口密钥。
- 增加真实账号、跨设备同步和社区权限。
- 在完成后端、实名认证、隐私与安全审核后再评估组队功能。
- 接入官方或授权购票跳转。
- 扩展全国城市覆盖和非干线交通。
- 根据真实行为数据调整推荐权重。

## 11. 已确认的关键决策

- 第一版是手机网页原型。
- 首页首屏直接提供规划输入。
- 同时展示极限省钱、均衡推荐和省时优先三套方案，由用户自行比较。
- 首页提供“下一站，未知”惊喜推荐模块。
- 目的地推荐使用四个排序按钮，同行类型作为筛选条件。
- 首页提供“旅人现场”优质内容模块。
- 社区内容和讨论绑定到相同或相似路线。
- 第一版使用模拟数据完成流程。
- 第一版支持实时查询接口结构和官方购票跳转能力，但真实数据权限到位前不伪造实时结果。
- 用户数据先保存在浏览器本地，不要求注册登录。
- 热门路线支持途径点，并按分段展示与估算。
- 底部导航为“首页、下一站、旅人现场、我的”。
- 第一版不开放组队和实名认证，也不显示不可用的组队入口。
